# CUDA Kernel Lab 设计说明

## 设计原则

- 保持独立项目边界
- 先有最小闭环，再逐步扩展
- 每个算子都尽量包含“实现 + 校验 + benchmark + profiling”
- 优先服务学习和分析，而不是抽象复杂度

## 目录设计

### `src/`

放可直接编译成可执行文件的 `.cu` 入口。

当前做法是：

- 每个示例先做成一个独立二进制
- 每个二进制内部自带：
  - 数据准备
  - kernel 启动
  - 正确性校验
  - 简单耗时统计

这种方式比一开始拆成复杂库结构更适合学习。

### `include/cuda_lab/`

放公共头文件。

当前先保留最小公共能力：

- CUDA 错误检查宏

### `scripts/`

放常用脚本：

- 构建
- 运行
- `nsys` 分析
- `ncu` 分析

这样可以保证后续新增算子时，入口习惯一致。

## 扩展路线

后续如果算子数量变多，可以逐步演进到：

- `src/operators/`
- `src/benchmarks/`
- `src/common/`

但当前先不做过早抽象。
